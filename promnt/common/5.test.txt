ТЕСТИРОВАНИЕ (E2E-first, Kotest, Testcontainers, WireMock)

5.1 Общая стратегия тестирования
Основной тип тестов — e2e (end-to-end).
Юнит-тесты пишутся редко, - по запросу
По умолчанию предпочитай e2e, а не unit.

5.2 E2E тесты
Инструменты:
Kotest — основной тестовый фреймворк
Testcontainers — реальные зависимости (PostgreSQL и др.)
WebTestClient — тестирование HTTP API
Spring Boot Test context

Правила:
e2e тесты поднимают реальный Spring context
тестируют фичу целиком: controller → application → infra → БД

проверяют:
happy-path
основные ошибки (404, 400, 409 и т.п.)
валидацию входных данных
не мокать внутренние слои приложения

5.3 BaseIntegrationTest (обязателен)
Все e2e / integration тесты обязаны наследоваться от BaseIntegrationTest.
В BaseIntegrationTest:
конфигурация Spring Boot Test
запуск и настройка Testcontainers
инициализация PostgreSQL контейнера
общий ApplicationContext, который поднимается один раз на все e2e тесты

Запрещено:
дублировать запуск контейнеров в тестах
поднимать контекст отдельно для каждого теста

5.4 Stubs и внешние зависимости

Для стабов внешних HTTP-сервисов использовать WireMockServer.

Правила:
WireMock поднимается как часть тестового окружения
используется для:
внешних REST API
webhook’ов
сторонних сервисов
стабы описываются явно в тесте или в helper-классах
не использовать Mockito для HTTP-клиентов

5.5 Unit-тесты (редко)
Юнит-тесты допускаются в исключительных случаях:
чистая domain-логика
сложные бизнес-инварианты
алгоритмы без I/O
Правила для unit-тестов:

Kotest
без Spring context
мокать только публичные зависимости
не мокать приватные методы
не дублировать логику, уже покрытую e2e
